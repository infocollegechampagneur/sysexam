Aide-mémoire — Mettre à jour MonExamEnLigne

Que faire après un « Save to GitHub » · Collège Champagneur · serveur VM Ubuntu + Docker + Cloudflare Tunnel

Règle n° 1 : un push GitHub ne met rien à jour tout seul. GitHub n'est que la copie de référence du code. Il faut ensuite déployer vers l'endroit concerné : la VM (API), SiteGround (site web) ou les postes (application Windows).

1. Où va quoi ?

GitHub infocollegechampagneur/sysexam
Code source, historique, fabrication automatique du site et du .msi (onglet Actions).
VM école /opt/monexam
API (FastAPI) dans Docker, exposée par Cloudflare Tunnel : https://api-examen.champagneur.qc.ca
SiteGround
Fichiers du site web : https://examen.champagneur.qc.ca (ce que voient enseignants et élèves).
MongoDB Atlas
La base de données (comptes, examens, copies). Jamais touchée par une mise à jour.

3. Mettre à jour l'API (VM) — 2 à 3 min

À faire hors période d'examen (coupure de 5 à 20 secondes pendant le redémarrage).

  1. Connexion SSH à la VM (PuTTY / Terminal) : ssh adminexam@192.168.x.x
  2. Lancer la mise à jour : 
    cd /opt/monexam
./mise-a-jour.sh
    Le script fait : git pull → reconstruction de l'image api → redémarrage (--profile tunnel détecté automatiquement grâce à TUNNEL_TOKEN dans ecole.env) → docker compose ps.
  3. Vérifier : 
    docker compose ps                      # mongo, api, tunnel : running / healthy
docker compose logs api | tail -20     # « Application startup complete », aucune ligne ERROR
curl -s https://api-examen.champagneur.qc.ca/api/   # {"message":"MonExamEnLigne API"}
Attendu Les 3 conteneurs en running, api passe à healthy en ~1 min, le curl renvoie le JSON. Sur Cloudflare → Networking → Tunnels, monexam = HEALTHY.
Si api reste en « Restarting » → docker compose logs api | tail -40. Cause fréquente : une nouvelle variable attendue dans ecole.env (KeyError: 'NOM_VARIABLE'). Ajoutez la ligne (nano ecole.env, modèle dans ecole.env.exemple) puis docker compose --profile tunnel up -d.

4. Mettre à jour le site web (SiteGround) — 10 min

  1. GitHub → dépôt sysexam → onglet Actions → à gauche, workflow Site web → bouton Run workflow.
  2. Champ backend_url : https://api-examen.champagneur.qc.ca → Run workflow. (Toujours cette adresse : c'est elle qui relie le site à la VM. Jamais l'adresse Render.)
  3. Attendez le crochet vert (2–3 min) → cliquez sur l'exécution → section Artifacts → téléchargez le ZIP.
  4. Décompressez le ZIP sur votre PC.
  5. SiteGround → Site Tools → Site → Gestionnaire de fichiers (ou client FTP FileZilla) → dossier de examen.champagneur.qc.ca (généralement public_html du sous-domaine).
  6. Téléversez tout le contenu du ZIP en remplaçant les fichiers existants. Le fichier .htaccess doit être présent (fichiers cachés : activez « Afficher les fichiers cachés » si besoin).
  7. Navigateur : https://examen.champagneur.qc.ca → Ctrl+F5 → connexion enseignant → vérifier la nouveauté.
Attendu Connexion réussie, vos examens apparaissent. Si le site « tourne en rond » ou affiche une erreur réseau : le backend_url était faux, ou le cache n'est pas vidé (navigation privée pour tester).
Pourquoi le ZIP et pas un simple copier-coller des fichiers GitHub ? Le site doit être « compilé » (React) avec la bonne adresse d'API. Le workflow s'en charge : vous ne téléversez jamais le dossier frontend/ brut.

5. Mettre à jour l'application Windows (postes élèves) — quand desktop/ change

  1. GitHub → desktop/package.json → crayon ✏️ → augmentez "version" (ex. 1.2.9 → 1.2.10) → Commit changes.
  2. Onglet Actions → workflow Desktop Windows → attendez le crochet vert → Artifacts (ou Releases) → téléchargez le .msi.
  3. Déployez par GPO comme d'habitude. Testez sur un poste : PreCheck, Antidote / WordQ / Lexibar, remise d'un examen test.

L'application Windows charge le site SiteGround : une mise à jour du site (§ 4) est donc visible immédiatement dans l'application, sans nouveau .msi. Le .msi n'est nécessaire que pour des changements de l'application elle-même (kiosque, détection de logiciels, PreCheck…).

7. Ce qu'il ne faut PAS faire

Modifier des fichiers directement sur la VM avec nano (sauf ecole.env)Le prochain git pull échouera (conflit). Toute modification de code passe par Emergent → GitHub.
Mettre ecole.env ou des mots de passe dans GitHubecole.env n'existe que sur la VM. Secrets = jamais dans le dépôt, jamais en clair dans une capture d'écran.
Lancer ./mise-a-jour.sh pendant un examenCoupure de quelques secondes → élèves déconnectés momentanément. Attendre la fin.
Supprimer la ligne DNS api-examen (Cloudflare) ou le tunnelL'API devient injoignable. Si cela arrive : recréer le CNAME api-examen → TUNNEL-ID.cfargotunnel.com (nuage orange).
Option pour plus tard Le workflow « Site web » peut déposer les fichiers directement sur SiteGround par FTP (identifiants FTP stockés comme secrets GitHub). Un push = site à jour, sans téléversement manuel. À demander à l'agent le jour où la routine FTP devient lourde.
