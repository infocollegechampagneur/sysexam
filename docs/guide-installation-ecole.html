Installer le serveur MonExamEnLigne à l'école

Guide pas à pas pour débutant — VM Ubuntu Server + Docker, en remplacement de Render

Résultat à la fin de ce guide :

  • le serveur d'examens tourne sur une machine virtuelle de l'école, allumée en permanence, sans mise en veille ni quota ;
  • il est joignable en https://api-examen.VOTREDOMAINE.qc.ca depuis l'école et de la maison ;
  • vos données actuelles (comptes, examens, classes, copies) sont rapatriées ;
  • le site SiteGround et l'application Windows pointent vers ce serveur ;
  • sauvegardes automatiques chaque nuit, mise à jour en une commande.
Temps : environ 2 h en tout, réparties sur 1 ou 2 jours (le DNS doit se propager). Version : juin 2026.

1. Comment ça marche (schéma en mots)

QuiRôleOù
GitHubGarde le code et son historique. Le bouton « Save to GitHub » d'Emergent l'alimente. Il n'exécute rien.Internet (déjà en place)
VM UbuntuExécute l'API (le « cerveau ») et la base de données MongoDB (les données), via 3 « conteneurs » Docker : api, mongo, caddy (HTTPS automatique).À l'école (à créer)
SiteGroundAffiche le site web (les pages). Il appelle l'API de la VM. Inchangé, sauf l'adresse de l'API.Internet (déjà en place)
Application WindowsSur les postes élèves ; appelle aussi l'API de la VM.Postes (GPO)

Docker, en une phrase : un programme qui fait tourner des logiciels dans des « boîtes » prêtes à l'emploi, que l'on démarre et met à jour avec une seule commande. Vous n'aurez jamais à installer Python ou MongoDB vous-même.

Convention dans ce guide Les commandes à taper sont dans des cadres noirs. Tapez-les (ou copiez-collez) une ligne à la fois, puis Entrée. Remplacez partout VOTREDOMAINE.qc.ca par votre vrai domaine et 192.168.10.50 par l'IP de votre VM. Les lignes qui commencent par # sont des commentaires : inutile de les taper.

3. Étape A — Créer la machine virtuelle et installer Ubuntu (30 min)

A1. Créer la VM dans votre hyperviseur

  • Nom : monexam · Génération 2 / UEFI si proposé · 2 processeurs · 4096 Mo de mémoire (fixe, pas dynamique) · disque 40 Go.
  • Réseau : la carte réseau doit être sur le même réseau que vos serveurs (commutateur « externe » dans Hyper-V).
  • Lecteur DVD : l'ISO Ubuntu Server téléchargée. Dans Hyper-V : désactivez « Secure Boot » ou choisissez le modèle « Microsoft UEFI Certificate Authority ».
  • Réglez la VM pour démarrer automatiquement avec l'hôte (Hyper-V : Paramètres → Action de démarrage automatique → Toujours démarrer).

A2. Installer Ubuntu (suivez l'assistant, flèches + Entrée)

  1. Démarrez la VM. Choisissez Try or Install Ubuntu Server.
  2. Langue : Français (ou English). Disposition du clavier : French (Canada).
  3. Type d'installation : Ubuntu Server (pas « minimized »).
  4. Réseau : sélectionnez la carte (ex. eth0) → Edit IPv4 → Manual :
    Subnet 192.168.10.0/24 · Address 192.168.10.50 · Gateway 192.168.10.1 · Name servers 192.168.10.1 (ou votre DNS interne) · puis Save, Done.
  5. Proxy : laissez vide. Miroir : laissez tel quel. Disque : Use an entire disk, décochez « Set up this disk as an LVM group » (plus simple), Done, confirmez Continue.
  6. Profil : Your name Admin Examen · Server name monexam · Username adminexam · Mot de passe solide (notez-le !).
  7. Ubuntu Pro : Skip for now.
  8. SSH Setup : cochez Install OpenSSH server (indispensable pour se connecter depuis votre PC).
  9. Featured snaps : ne cochez rien (on installera Docker autrement). Done.
  10. Attendez la fin, puis Reboot Now. Si le message « remove the installation medium » apparaît, retirez l'ISO du lecteur virtuel et appuyez sur Entrée.
Vérification A Après le redémarrage, l'écran affiche monexam login:. Connectez-vous avec adminexam et votre mot de passe. Tapez ip a : vous devez voir 192.168.10.50. Tapez ping -c 3 google.com : 3 réponses = Internet fonctionne.

4. Étape B — Se connecter à la VM depuis votre PC (5 min)

Plutôt que de taper dans la console de l'hyperviseur, on travaille depuis son PC Windows avec SSH (copier-coller possible).

  1. Sur votre PC : Win + X → Terminal (ou PowerShell).
  2. Tapez : 
    ssh adminexam@192.168.10.50
  3. À la question « Are you sure you want to continue connecting? », tapez yes. Entrez le mot de passe (rien ne s'affiche pendant la saisie, c'est normal).
Vérification B L'invite devient adminexam@monexam:~$. Vous êtes « dans » la VM. Pour coller une commande : clic droit dans le Terminal. Pour quitter : exit.

5. Étape C — Adresse Internet : DNS et pare-feu (10 min + attente)

C1. DNS — créer le sous-domaine

Chez votre registraire (là où est géré VOTREDOMAINE.qc.ca), section DNS / Zone DNS / Gestion des enregistrements, ajoutez :

TypeNom (hôte)Valeur (pointe vers)TTL
Aapi-examenIP publique de l'école (ex. 204.19.xx.xx)600 (ou « 10 min »)

Si l'interface demande le nom complet, écrivez api-examen.VOTREDOMAINE.qc.ca. Ne touchez à rien d'autre (le site examen.… et le courriel restent tels quels).

C2. Pare-feu — rediriger 2 ports vers la VM

Dans le pare-feu/routeur de l'école, créez deux règles de redirection de port (« Port forwarding », « NAT », « Virtual IP », « DNAT » selon la marque) :

ProtocolePort externe (WAN)Vers l'IP internePort internePourquoi
TCP80192.168.10.5080Obtention/renouvellement automatique du certificat HTTPS
TCP443192.168.10.50443Le trafic HTTPS de l'application
Si la TI refuse d'ouvrir des ports Passez par l'annexe B (Cloudflare Tunnel, gratuit, aucun port entrant). Le reste du guide reste identique.
Vérification C (après 10 à 60 min de propagation) Sur votre PC : nslookup api-examen.VOTREDOMAINE.qc.ca → la réponse doit contenir l'IP publique de l'école. Le test du pare-feu se fera à l'étape G.

6. Étape D — Installer Docker (10 min)

Dans la fenêtre SSH, collez ces commandes une à la fois (acceptez avec Entrée ou o/y si on vous le demande) :

# 1. Mises à jour du système
sudo apt update && sudo apt -y upgrade
# 2. Outils de base
sudo apt -y install ca-certificates curl git
# 3. Docker (script officiel)
curl -fsSL https://get.docker.com | sudo sh
# 4. Permettre à votre utilisateur d'utiliser Docker sans sudo, et démarrer Docker au boot
sudo usermod -aG docker $USER
sudo systemctl enable docker
# 5. Fuseau horaire et pare-feu de la VM elle-même
sudo timedatectl set-timezone America/Toronto
sudo ufw allow OpenSSH
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw --force enable

Puis tapez exit, et reconnectez-vous (ssh adminexam@192.168.10.50) pour que le droit Docker soit pris en compte.

Vérification D docker compose version affiche « Docker Compose version v2.x ». docker run --rm hello-world affiche « Hello from Docker! ».

7. Étape E — Autoriser la VM à lire votre dépôt GitHub (5 min)

Votre dépôt est privé : la VM a besoin d'une « clé » en lecture seule. On utilise un jeton d'accès.

  1. Sur github.com, connecté : cliquez sur votre photo (en haut à droite) → Settings → tout en bas à gauche Developer settings → Personal access tokens → Fine-grained tokens → Generate new token.
  2. Token name : VM monexam. Expiration : 1 year (notez la date dans votre agenda). Repository access : Only select repositories → choisissez votre dépôt.
  3. Permissions → Repository permissions → Contents : Read-only. (Metadata se coche automatiquement.) → Generate token.
  4. Copiez le jeton (commence par github_pat_…) : il ne sera plus jamais affiché. Gardez-le dans votre gestionnaire de mots de passe.

Le jeton sera utilisé une seule fois à l'étape F ; Git le mémorise ensuite sur la VM. Si l'organisation GitHub exige l'approbation des jetons, un administrateur de l'organisation doit l'approuver (Organisation → Settings → Personal access tokens).

8. Étape F — Récupérer le code et remplir la configuration (15 min)

F1. Télécharger le code

cd /opt
sudo git clone https://github.com/VOTRE-COMPTE/VOTRE-DEPOT.git monexam
# Username : votre identifiant GitHub   Password : collez le jeton github_pat_… (clic droit)
sudo chown -R $USER:$USER /opt/monexam
cd /opt/monexam
git config credential.helper store
git pull   # redemandera une dernière fois le jeton, puis le mémorise

F2. Créer le fichier de configuration

cp ecole.env.exemple ecole.env
openssl rand -hex 32     # génère une clé secrète : copiez le résultat pour JWT_SECRET
nano ecole.env

nano est un petit éditeur : déplacez-vous avec les flèches, modifiez, puis Ctrl+O, Entrée pour enregistrer et Ctrl+X pour quitter. Remplissez chaque ligne sans guillemets ni espaces autour du = :

LigneQue mettre
API_DOMAINapi-examen.VOTREDOMAINE.qc.ca (exactement le nom créé à l'étape C)
MONGO_URLLaissez mongodb://mongo:27017 (base de données locale, recommandé)
DB_NAMEmonexam
FRONTEND_URLL'adresse du site sur SiteGround, ex. https://examen.VOTREDOMAINE.qc.ca (sans / à la fin)
CORS_ORIGINSLa même valeur que FRONTEND_URL
JWT_SECRETLe résultat de openssl rand -hex 32. Important : si vous préférez que les enseignants restent connectés pendant la bascule, copiez plutôt la valeur JWT_SECRET de Render.
ADMIN_EMAIL / ADMIN_PASSWORDCompte admin créé uniquement si la base est vide. Comme vous importerez vos données (étape H), mettez n'importe quoi de solide ; vos comptes actuels seront conservés.
APP_TIMEZONEAmerica/Toronto
SMTP_HOST … MAIL_FROM_NAMECopiez exactement les valeurs de Render → Environment (SMTP2GO).
Ne partagez jamais ce fichier ecole.env contient vos mots de passe. Il reste sur la VM uniquement (il est exclu de GitHub).

9. Étape G — Démarrer le serveur et vérifier le HTTPS (10 min)

cd /opt/monexam
docker compose up -d --build
# première fois : 2 à 5 minutes de téléchargement et de construction
docker compose ps

Vous devez voir trois lignes monexam-mongo-1, monexam-api-1, monexam-caddy-1 avec l'état running (et healthy pour mongo et api après ~1 min).

docker compose logs -f api      # doit finir par « Application startup complete » ; Ctrl+C pour sortir
docker compose logs caddy | tail -20   # doit mentionner « certificate obtained successfully »
Vérification G (la plus importante)
  1. Depuis la VM : curl -s http://localhost:80 renvoie une redirection, c'est normal.
  2. Depuis un téléphone en données cellulaires (Wi-Fi désactivé), ouvrez https://api-examen.VOTREDOMAINE.qc.ca/api/ → vous devez voir {"message":"MonExamEnLigne API"} avec le cadenas. C'est la preuve que DNS + pare-feu + certificat fonctionnent.
  3. Depuis un PC de l'école, même adresse. Si ça échoue ici mais marche au point 2, voir Dépannage n° 5 (DNS interne).

10. Étape H — Rapatrier les données depuis Render / Atlas (10 min)

Vos comptes, classes, examens et copies sont actuellement dans MongoDB Atlas. On les copie dans la base de la VM. À faire hors période d'examen, idéalement le soir même de la bascule.

  1. Dans Render → votre service → Environment, copiez la valeur de MONGO_URL (commence par mongodb+srv://) et celle de DB_NAME (ex. monexam_prod).
  2. Sur la VM, remplacez les deux valeurs et collez : 
    cd /opt/monexam && mkdir -p sauvegardes
ATLAS='COLLEZ_ICI_MONGO_URL_DE_RENDER'
NOM='COLLEZ_ICI_DB_NAME_DE_RENDER'
docker compose exec -T mongo sh -c "mongodump --uri='$ATLAS' --db='$NOM' --archive --gzip" > sauvegardes/atlas.gz
ls -lh sauvegardes/atlas.gz      # la taille doit être > 0
docker compose exec -T mongo sh -c "mongorestore --archive --gzip --nsFrom='$NOM.*' --nsTo='monexam.*' --drop" < sauvegardes/atlas.gz
docker compose restart api
  3. La dernière commande mongorestore se termine par « X document(s) restored successfully, 0 document(s) failed ».
Les fichiers PDF/Word des examens sont stockés dans la base (GridFS) : ils font partie de la copie. Rien d'autre à transférer.
Vérification H Dans un navigateur : https://api-examen.VOTREDOMAINE.qc.ca/api/ répond toujours. La vraie vérification se fera à l'étape I en vous connectant avec votre compte habituel.

11. Étape I — Brancher le site SiteGround et l'application Windows (20 min)

I1. Le site web (SiteGround)

  1. Sur github.com → votre dépôt → onglet Actions → dans la liste de gauche Site web → bouton Run workflow → champ backend_url : https://api-examen.VOTREDOMAINE.qc.ca → Run workflow.
  2. Attendez le crochet vert (2-3 min), cliquez sur l'exécution, section Artifacts : téléchargez l'archive ZIP du site.
  3. Décompressez-la et téléversez tout son contenu dans public_html (ou le dossier de examen.VOTREDOMAINE.qc.ca) via le FTP SiteGround ou le Gestionnaire de fichiers, en remplaçant les anciens fichiers. Le fichier .htaccess fourni doit être présent (routes et cache).
  4. Ouvrez https://examen.VOTREDOMAINE.qc.ca, forcez un rechargement (Ctrl+F5), cliquez Espace enseignant et connectez-vous avec votre compte habituel.
Vérification I1 Vous êtes connecté·e et vous voyez vos examens existants. Créez un examen test, ouvrez-le, puis depuis une fenêtre de navigation privée rejoignez-le comme élève, répondez, remettez. Le tout depuis l'école et depuis la maison (ou téléphone en cellulaire).

I2. L'application Windows (postes élèves)

  1. Dans le dépôt GitHub, ouvrez desktop/config.json → crayon ✏️ → remplacez l'adresse dans "url" par https://examen.VOTREDOMAINE.qc.ca si elle a changé, et vérifiez qu'aucune adresse Render n'y figure. Commit changes.
  2. Ouvrez desktop/package.json → augmentez "version" (ex. 1.2.8 → 1.2.9) → Commit changes. GitHub produit un nouveau .msi (onglet Actions → Desktop Windows → Artifacts, ou Releases).
  3. Déployez le .msi par GPO comme d'habitude. Testez sur un poste : PreCheck, Antidote/WordQ/Lexibar, remise.

Remarque : l'application Windows charge le site SiteGround, qui lui-même appelle l'API. Si l'adresse du site n'a pas changé, l'étape I2 n'est pas strictement nécessaire, mais une nouvelle version est recommandée pour purger les caches.

I3. Éteindre Render

  • Render → votre service → Settings → Suspend service (vous pourrez le réactiver en cas de besoin). Dans le dépôt GitHub, supprimez le fichier .github/workflows/keep-awake.yml (plus utile).
  • Gardez Atlas intact 2 à 4 semaines comme filet de sécurité, puis supprimez le cluster si vous le souhaitez.

12. Étape J — Sauvegardes automatiques (5 min)

Le script sauvegarde.sh crée chaque nuit une archive de la base (sauvegardes/monexam_DATE.gz) et garde 30 jours.

cd /opt/monexam
./sauvegarde.sh                 # test immédiat : affiche « Sauvegarde OK : … »
crontab -e                      # choisissez « 1 » (nano) si on vous demande l'éditeur

Tout en bas du fichier, ajoutez cette ligne, puis Ctrl+O, Entrée, Ctrl+X :

30 2 * * * cd /opt/monexam && ./sauvegarde.sh >> sauvegardes/journal.log 2>&1
Une sauvegarde sur la même machine ne suffit pas Faites aussi : (1) une sauvegarde de la VM entière par l'hyperviseur chaque semaine, et/ou (2) une copie du dossier /opt/monexam/sauvegardes vers un NAS ou OneDrive. Exemple de copie vers un partage Windows : installez cifs-utils et ajoutez un cp dans la tâche cron, ou utilisez l'agent de sauvegarde de votre hyperviseur.

Restaurer (en cas de besoin) : docker compose exec -T mongo mongorestore --archive --gzip --drop < sauvegardes/monexam_2026-10-27_0230.gz puis docker compose restart api.

14. Dépannage : les 12 problèmes les plus fréquents

1. ssh : « Connection refused » ou aucune réponse.
OpenSSH n'a pas été coché à l'installation : dans la console de la VM, sudo apt -y install openssh-server. Vérifiez aussi l'IP (ip a).
2. docker : « permission denied ».
Vous ne vous êtes pas reconnecté après usermod. Tapez exit puis reconnectez-vous en SSH.
3. git clone : « Authentication failed ».
Le mot de passe GitHub ne fonctionne pas : il faut coller le jeton (étape E). Vérifiez qu'il a accès à ce dépôt et la permission Contents.
4. docker compose ps : api est en « Restarting ».
docker compose logs api. Causes typiques : une ligne de ecole.env manquante (KeyError: 'FRONTEND_URL'…), guillemets en trop, ou MONGO_URL erroné.
5. Ça marche en cellulaire mais pas depuis l'école.
« NAT hairpin » : dans votre DNS interne (serveur Windows/AD → DNS → zone VOTREDOMAINE.qc.ca ou nouvelle zone api-examen.VOTREDOMAINE.qc.ca), créez un enregistrement A → 192.168.10.50. Testez avec ipconfig /flushdns puis nslookup.
6. Ça marche depuis l'école mais pas en cellulaire.
Redirection de ports 80/443 absente ou vers la mauvaise IP, ou le DNS public n'est pas encore propagé (nslookup api-examen.VOTREDOMAINE.qc.ca 8.8.8.8). Vérifiez aussi que votre FAI ne bloque pas le port 80/443 (certains forfaits résidentiels).
7. Le navigateur dit « connexion non privée » / pas de certificat.
docker compose logs caddy. Caddy a besoin du port 80 ouvert et du DNS public correct pour obtenir le certificat. Corrigez, puis docker compose restart caddy. Let's Encrypt limite les essais : attendez 1 h entre deux tentatives ratées.
8. Le site s'affiche mais la connexion enseignant tourne en rond / erreur réseau.
Le site appelle encore Render : refaites l'étape I1 avec la bonne backend_url et videz le cache (Ctrl+F5). Ou FRONTEND_URL/CORS_ORIGINS dans ecole.env ne correspond pas exactement à l'adresse du site (https, sans / final).
9. Mes examens n'apparaissent pas après la connexion.
L'import (étape H) a été fait dans un autre nom de base : DB_NAME dans ecole.env doit être monexam (le --nsTo de l'import). Relancez l'import si besoin.
10. Les courriels (bienvenue, alertes d'aide) ne partent pas.
Variables SMTP_* incomplètes dans ecole.env, ou le port 2525/587 sortant bloqué par le pare-feu de l'école : autorisez-le vers mail.smtp2go.com.
11. Le disque se remplit.
df -h. Nettoyez les anciennes images Docker : docker system prune -af. Les sauvegardes de plus de 30 jours sont supprimées automatiquement ; déplacez-les ailleurs si besoin.
12. Panne de courant / VM qui ne redémarre pas seule.
Dans l'hyperviseur, activez le démarrage automatique de la VM. Dans la VM, sudo systemctl is-enabled docker doit répondre « enabled ». Les conteneurs ont restart: unless-stopped.

15. Annexes

A. Garder MongoDB Atlas (sans base locale)

Dans ecole.env : MONGO_URL= la chaîne Atlas de Render et DB_NAME= la même valeur que Render ; sautez l'étape H. Le conteneur mongo tourne alors inutilement (sans conséquence). Limites gratuites Atlas : 512 Mo et 500 connexions ; pour 250-500 élèves qui sauvegardent toutes les 5 secondes, la base locale reste le choix recommandé (plus rapide, sans plafond, sauvegardée par vous).

B. Cloudflare Tunnel (si aucun port ne peut être ouvert)

  1. Créez un compte gratuit sur cloudflare.com, Add a domain → votre domaine → forfait Free. Cloudflare vous donne 2 serveurs de noms : changez les « nameservers » chez votre registraire. Le site SiteGround et vos courriels continuent de fonctionner (Cloudflare recopie vos enregistrements ; vérifiez-les).
  2. Cloudflare → Zero Trust → Networks → Tunnels → Create a tunnel → Cloudflared, nom monexam. Choisissez Docker et copiez le long jeton après --token.
  3. Sur la VM, nano docker-compose.yml et ajoutez sous services: (respectez les 2 espaces d'indentation) : 
      tunnel:
    image: cloudflare/cloudflared:latest
    restart: unless-stopped
    command: tunnel --no-autoupdate run --token COLLEZ_LE_JETON_ICI
    depends_on: [api]
  4. Dans Cloudflare, onglet Public Hostname → Add : Subdomain api-examen, Domain votre domaine, Service HTTP → api:8001. Save.
  5. docker compose up -d. Testez https://api-examen.VOTREDOMAINE.qc.ca/api/. Le conteneur caddy et la redirection de ports deviennent inutiles (vous pouvez retirer le bloc caddy du fichier).
